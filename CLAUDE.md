## Architecture (V2)
- **Multi-tenant:** tables `clinics`, `profiles` (role: `patient` | `therapist` | `manager`; patients carry `therapist_id` = assigned PT), `checkins` (keyed on existing `user_id` + `clinic_id`), `consents`, `access_log`, `staff_invites`. Row-Level Security keeps each clinic private.
- **Staff invites (V2.1):** a manager invites a therapist by email (`invite_staff` RPC → `staff_invites` row); the therapist becomes staff on first sign-in (`accept_staff_invite` RPC, called from `loadProfile`) — role is set server-side so a patient can't self-promote. Manager assigns patients to therapists (`assign_therapist` RPC). Migration `supabase/migrations/0002_therapists.sql`.
- **Auth:** Supabase passwordless **6-digit email code** (OTP). Flow = `signInWithOtp` → user types the code into the same tab → `verifyOtp` (shared `CodeVerify` screen used by Login/Join/Onboard). Chosen over magic links because links open in whatever email app, breaking session persistence on phones; the code keeps everything in one tab. **Requires the Supabase "Magic Link" + "Confirm sign up" email templates to include `{{ .Token }}`.** Name/clinic/consent ride in signup **user_metadata** AND a localStorage backup saved by the form. **Gotcha (fixed 2026-07-13):** `signInWithOtp` `data`/user_metadata is only written for a BRAND-NEW email — ignored for an already-existing account. So `loadProfile` also falls back to the localStorage backup (incl. the name) — rely on that, not metadata alone, or a returning email's name/clinic goes blank. "Confirm email" is OFF. CodeVerify checks `getSession()` after `verifyOtp` and forwards into the app on success (an error only shows if truly not signed in).
- **AI:** patient text goes to the `ai-response` Edge Function (keeps PHI inside Supabase — HIPAA-*ready*).
- **Patient app (`PatientApp.jsx`):** welcome → daily check-in → AI reflection → **Progress screen** ("View my progress", built 2026-07-13). Progress is a stack of cards: consecutive-day **streak** (hero) → This-week + all-time counts → **"Your month"** card (avg-mood summary + 4 weekly-average bars showing the arc) → tappable **"This week"** card to read past entries. One 30-day `checkins` query powers week + trend + streak; all-time total via a count query. (Earlier it reused the post-checkin screen + showed 30 anonymous dots — both replaced.)
- **Dashboards:** manager = clinic-wide engagement + care-team management (invite therapists, assign patients); therapist = ONLY their assigned caseload (enforced by RLS, not just UI). Both show streaks, 7-day trend, and flags (Inactive 5+ days / Low-mood 2+ low days). Staff views write an `access_log` entry. **7-day trend shows the same emoji faces the patient taps at check-in** (not colored dots, as of 2026-07-14) — patient/manager/therapist share one language; triage is carried by the Status pills, not color. The 1–5 face + word scale (😔 Really tough → 😄 Feeling great) lives in ONE shared file `src/lib/feelings.js`, imported by both `PatientApp.jsx` and `Dashboard.jsx` so they can't drift. (Patient Progress-screen month bars still color by mood via a local `FEELING_COLOR` in `PatientApp.jsx`.)
- **Weekly emails (PHI-free nudges):** `weekly-summary` Edge Function computes numbers in Supabase and sends via Resend. Patient email = own name + check-in count + link; clinic email = aggregates only, no names. Scheduled: Supabase Cron `weekly_summary`, `0 12 * * 1` (Mon 8am ET).

- **✍️ COPY RULE — THE HOUSE STYLE FOR ALL UI TEXT (David's rule, set 2026-08-25; applied everywhere). Follow this for every new string.**
  - **STATEMENTS** — anything asserting something to the reader (headlines, sub-lines, prose, empty states, the tagline) — get **sentence case AND a terminal period**. Questions keep their `?`.
  - **LABELS** — screen titles, buttons, flag pills, section heads, micro-labels — get **Title Case and NO period**.
  - **⛔ NO ALL-CAPS ANYWHERE.** David's explicit call. All 16 `textTransform: 'uppercase'` styles were removed. **When you drop caps you must ALSO retune the type**: wide tracking is a convention *for* uppercase and looks like a glitch on Title Case, so letter-spacing went from ~0.1–0.2em down to **0.01em**, and the smallest sizes stepped up (9.5→11, 10→11.5, 11→12) because losing caps lowers apparent size. **Don't just delete the property and leave the tracking.**
  - **Empty/error states were REWRITTEN into sentences** (David chose this over title-casing them), so all three read alike: "You're not connected to a clinic yet." · "No clinic is linked yet." · "That link wasn't found." **The fragments are gone on purpose** — under the rule a fragment would be a label and a full clause a statement, which dressed three identical messages two different ways.
  - **📏 TITLE-CASE CONVENTIONS — David's rule, set 2026-08-25. Follow it exactly; it exists to remove judgement calls.**
    - **A preposition of FOUR OR MORE letters is CAPITALISED; three or fewer stays lowercase.** So `with`, `from`, `into`, `over`, `about`, `after`, `between`, `through`, `without`, `during`, `across` all get capitals, while `at`, `by`, `for`, `in`, `of`, `off`, `on`, `out`, `per`, `to`, `up` do not. (This is the AP Stylebook rule. **Chicago lowercases every preposition regardless of length — do NOT use Chicago here**, or the two will fight.)
    - Articles (`a`, `an`, `the`) and coordinating conjunctions (`and`, `but`, `or`, `nor`, `so`, `yet`) stay lowercase — unless first or last word, which is always capitalised.
    - **Phrasal-verb particles ARE capitalised even when short** — they are not prepositions: **Sign In**, **Sign Out**, **Sign-Up**.
    - Capitalise **both halves of a hyphenate**: **Last Check-In**, **Patient Sign-Up QR**, **3-Day Trend**.
    - **Audited 2026-08-25 across all 60 label strings: ZERO 4+ letter prepositions were sitting lowercase**, so adopting the rule changed nothing at the time. It governs new copy.
  - **Misses caught by that audit and fixed (a reminder that a scripted sweep is not a review):** `This week — tap a day` → **This Week — Tap a Day** (same `streakLabel` style as its already-fixed sibling); `Anything else?` → **Anything Else?** (same `qLabel` style as *Body Check* / *Movement*; the audit script skipped it because the lowercase word was last); the `streakHint` "Tap a completed day to read your entry" gained a period as a statement; and `Pending (waiting for first sign-in):` → **Pending (Waiting for First Sign-In):**.
- **🔗 INLINE LINKS INSIDE PROSE MUST BE A `<span role="button">`, NEVER A `<button>` (fixed 2026-08-26).** A `<button>` is an atomic inline-block: the browser will not break its text across lines. So in the consent sentences, "Business Associate Agreement" could not wrap, it filled line 1 exactly at iPhone-portrait width, and **the trailing period fell alone onto line 2** (landscape was fine, which is why it hid for so long). Both consent links — `Onboard.jsx` (BAA) and `Join.jsx` (privacy notice) — are now inline `<span role="button" tabIndex={0}>` with an `onKeyDown` for Enter/Space, so the phrase wraps like normal text and the period can never separate at any width.
